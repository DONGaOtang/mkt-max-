# 对抗审查与用途验收

适用：重要判断、方向选择/收敛、实质变更、可评审稿、完整交付或真实反馈的结论。局部改动集中新增/变化影响，不重跑无关全案。对抗不能代实际研究、创作、专业确认或受众验证。

## 先建立最强版本

在反对之前，准确复述当前方案的目标、人群所得、真实原料、具体内容、为什么可能成立、必要条件和作者范围。攻击它最强的版本，避免只挑错别字、被否弃方向或作者未承诺的制作深度。最强反驳可能是活动本身不必要、内容无用、对象不愿投入、证据不支持或兑现不能发生，而不是视觉不够炫。

判断先分事实/用户决定/创作拟案/效果假设，再问哪条证据能改变结论。内部观点审查可以高置信诊断逻辑矛盾，但不能据此宣称真实市场、用户接受、现场或脚本已验证。

## 主要攻击面与修复

| 攻击面 | 具体检查 | 失败后的实质动作 |
|---|---|---|
| 需求与必要性 | 是否回应真实委托/人群需要，是否有更合适方式，范围是否暗扩 | 修目标/范围/方式，给明确取舍而非只多加模块 |
| 证据与反例 | 关键声明原文真支持、同源、访问范围、时效/地域、相反材料和竞争解释 | 补原件/反证、缩声明、改条件/判断，不堆链接 |
| 内容与叙事 | 去掉名字/图片/修辞能否讲清主要内容和关系，是否全靠未定嘉宾/未来投稿 | 写实际单元、场景/稿件与衔接，核主体/替代 |
| 创意与审美 | 真实所得、项目专属性、形式适配、首次理解、观看/退出、身份和社交负担 | 改具体任务/画面/文案/服务，不强加互动/传播 |
| 承诺与服务 | 入口、接收、响应、库存/容量、权益及售后是否可用，拒拍/不参与是否有约定核心服务 | 修规则/入口/接收或改承诺，无法兑现不称可执行 |
| 制作与资源 | 班次/同时工作、技术/场地、素材/权限、规格、生产时滞、专业条件 | 修排产/任务/资源与替代，实际复验，不虚构资质 |
| 商业与数值 | 数量/公式/税币种、唯一成本、范围付款、库存排他、取消/变更 | 修主账/权益/合同接口，不用高分抵重复计费 |
| 数据与效果 | 定义、基线、分母/窗口/去重、数据/权限、缺失、目标/预测/实绩、归因/增量 | 改口径/采集/结论，不能用行业比例补未知 |
| 一致性与变更 | 内容、规则、公开文本、制作、培训、人物状态和成本是否同一有效版本 | 沿依赖改真实正文/成品/通知状态，再回读 |
| 文件与接手 | 真实交付物、格式/编辑、附件/版本、接手能完成动作 | 生成/修实际工作件，目录/摘要不能抵交 |
| 上下文与恢复 | 全目录/实际读取是否混淆，摘要漏例外，版本/截断/保存是否可信 | 回原件、缩包/分段、保存与恢复复核，不减深度 |

每项重要问题给受影响对象/具体段、证据或准确未知、成立/失效条件、严重影响、最强反驳、可行修法/备选损失、补查/负责人/期限和复验。不能以“注意、加强、优化、谨慎”作修法。尚无数据的反例是明示推演，不伪称投诉/市场反馈。

## 按用途验收实际产物

| 当前用途 | 必须实际得到什么 | 不能冒称 |
|---|---|---|
| 研究/诊断 | 问题、实际已读来源、判断/反证、充分性、影响及缺口 | 查过题名等于全文、研究完成等于内容已交 |
| 方向/概念 | 连贯活动介绍、具体内容原型/场景、单元与体验关系、条件与必要参考 | 目录/闪卡就是完整概念，资源已落实 |
| 决策/正式评审 | 完整本次内容、推荐及取舍、费用/条件和需要的决定 | 模型推荐等于客户批准 |
| 执行/服务交接 | 内容/规则、人员/班次/培训、时序/技术/规格/资源、接口及异常 | 工作表列齐等于现场可跑，计划等于已培训/验收 |
| 文案/设计/制作 | 约定实际文字/图稿/原生源件、规格/附件/版本及真实接收 | Brief/分镜/截图代图稿/源件，改后缀代格式 |
| 线上/传播 | 约定实际稿件/素材/Brief、真实账号/入口、接收回应与权益/数据 | 日历等于成稿，合作稿等于自然好评，写稿等于已发 |
| 商业/赞助 | 范围/价格依据、唯一成本、库存/权利/排他、付款验收与履约证据 | 意向/舞台签约等于到账，估值等于现金 |
| 系列 | 实质各单元、场次/资产/资源/费用/指标关系、日历及更新价值/产能 | 日期变化是新作，人次合计为独立人数 |
| 复盘/学习 | 真实数据、质量/缺失、条件、观察、竞争解释、改动与迁移边界 | 待采模板是实绩，单次观察是通用规律 |

不是每案九套文件。对应深度的关键内容、证据或文件缺失不能被其他优点抵消；概念用途不因没约定施工图一概退回，但实际依赖未核的执行件不能称可直接执行。

## 真实阅读与代表接手动作

审查从实际正文/成品/原件开始，不只读作者摘要、文件名和状态表。全文需求分批覆盖全部范围并保存已读/未读位置；局部接口读相关条款及上下文，查例外和实质间接依赖。必要原作/规则/预算公式和视觉页/帧实际回读，申报read_scope不证明阅读已经验证。

按本次承诺选择有区分度的接手动作，例如让制作方按实际文案找到使用位置/规格/源件，让运行方按规则执行一轮并处理异常，让接收方从页面提交走到回应/兑现，让财务对一个费用和权益查来源/唯一入账/验收。规范中的检查方法不是已经发生的验证，操作必须记录真实材料/版本、步骤、结果、失败、限制和修复后复验。

全案核主要单元及前后关系，共同名称、时间地点/入口、作品/人物状态、规则/费用/权益、人数口径、技术/资源和素材/服务一致；索引完整不代正文完成。系列核一实际场次、一天内容、复演/共享，以及已有或明示模拟的一次改期/取消；不为验收创造项目本不需要的传播/销售。

允许评分辅助候选比较时，提前说明维度/尺度/权重的项目依据，不设统一百分制/放行线、不事后改权重偏向结果。分数是审阅判断，不能抵核心空白、虚构证据、缺约定文件、权益冲突和不可兑现，更不表示真实效果。

## 证据层次与结论

分别报告方法/逻辑一致、文件/结构完成、当前用途内容可用、用户决定、资源/专业确认、外部执行、真实受众理解和实际结果。脚本成功、链接检查、文件能打开或模型评分只支持对应层次，不能升级其他层次。

| 可用判词 | 附带的准确边界 |
|---|---|
| 本次用途通过 | 实际文件/版本、已经检查的内容/操作、来源/条件及未检范围 |
| 条件可评审 | 不阻断本次判断但仍待核的条件、接收责任/节点，不能称可直接执行 |
| 待修改与复核 | 具体问题、真实修订对象、依据和再检查，不提前说“修改后通过” |
| 阻断相关定稿 | 为什么影响本次用途，需什么证据/决定，其他独立工作继续 |
| 未验证/未知 | 没有实际数据、操作或能力，列真实缺口不编结论 |

重要结论附高/中/低/未知置信度及其证据范围；用户提出不同意见而无新证据，不为讨好改变成立推理。新事实/更强论据出现时改对应判断及受影响工作件，非方向细节不全案重启。

## 独立接续与改进边界

复杂技能或交付需要独立读者验证且有授权/能力时，给新的接收者真实请求、技能和必要原始材料，不给预期答案、实现前结论或暗示缺陷，让其按文件完成任务；不让实现者自己的多角色扮演冒充独立评审。继承全部聊天的子Agent不是真冷读，要准确说明上下文性质。

保留实际输出/证据、遗漏、失败与修复，按示范行为而非字符串命中判断。若验证只做桌面/合成输入，明示范围，不能称真实客户、现场或市场已验证。项目经验先在项目目录，实际验证且明确采纳后才改通用方法；不因一个反例增加永久硬规则。
