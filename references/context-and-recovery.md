# 上下文预算、保存与恢复

适用：长任务、多资料、阶段/模块切换、大工具结果、中断/压缩、新对话或协作。先读宿主预检与当前控制状态，再读需要的任务包、转存、检查点或全案节。完整档案保留在文件中，轻入口不意味着删减内容深度。

## 宿主能力预检

只检查本轮需要的能力，结果标真实可用/受限/未知与证据，缺失按表处理，不承诺不可用能力。

| 能力 | 实际需要核什么 | 不具备时的处理 |
|---|---|---|
| 文件访问/持久保存 | 当前工作根、可读写原件/候选、保存后能回读 | 明确不能提供同样文件接续，保留可用导出与未保存状态 |
| 搜索/页面/登录 | 工具、来源范围、权限及真实访问 | 换有权公开/原始路径，保留缺口和条件推进 |
| 图像/PDF/视频 | 能观察的图/页/帧/时段，文字/视觉各自范围 | 记录未见内容，不虚构画面/成品判断 |
| 分词统计 | 实际编码/工具、版本与测量对象 | 比较估算或机械大小明确命名，不当真实消耗 |
| 当前上下文遥测 | 当前会话可靠容量/使用快照、时间与新鲜度 | 标未知，依工作信号减量，不报猜测百分比 |
| 压缩/新窗口 | 当前宿主真实支持和已有授权 | 显式保存并用可用方式接续，不承诺自行清空 |
| 启动/压缩前钩子 | 是否真的可接入并已生效 | 显式初始化/续接和实质单元保存，不能只等钩子 |
| 子Agent隔离 | 是否继承全聊天、文件权限/读写与工具 | 串行或限定任务；继承历史不叫独立隔离 |
| 原生文件生产 | 当前Word/PPT/表格/图稿/源件真实能力 | 保留源稿，标约定原生件未交，格式另核 |

账户五小时/周额度、累计token、目标预算、文件字节数和缓存命中均不是当前窗口占用。读取可用遥测只取已核当前会话的必要字段，不输出整个聊天、凭据或遍历他人会话；过时/身份不匹配/发生压缩后的旧快照保留时间戳，当前占用仍标未知。

## 可选 Codex 遥测与压缩前保存

`scripts/context_guard.py` 是标准库适配器；启用以本机实际支持的接口为准。显式绑定当前 `session_id`、transcript 原件、工作根、项目和授权范围，只读该会话的必要事件。取最近单次请求用量、窗口字段、事件时间及压缩代次；累计 thread／turn 用量不作占用，缓存输入不从窗口扣除。会话身份不匹配、事件过旧、压缩后尚无新用量或格式不支持时标 `unknown` 并说明原因。文件 mtime 不证明事件新鲜。

这个比值是“最近一次请求用量与窗口的比较信号”，有更新延迟，新工具返回与正在生成的内容可能尚未计入。不能称此刻精确占用，也不能保证在某个百分比前一定救回所有内容。拿不到窗口字段就不能计算比值。上下文的精确剩余仍只在宿主提供可信实时值时表达。

当前 Codex 官方接口含 `PreCompact`，可在自动或手动压缩前同步调用保存脚本；`PostModelRequest` 提供单次用量、用于诊断。模型请求前后事件不能修改上下文或阻止请求。适配器只处理显式映射的项目，会话未映射就不写项目，不根据传入 cwd 猜项目。压缩前保存复用实际已有分类及已声明工作文件，再生成接续入口；不阻止压缩，不把失败说成成功。[官方 OpenAI Hooks 文档](https://learn.chatgpt.com/docs/hooks)

仓库附 `hooks.example.json` 供按实际安装路径配置。**样例存在、命令自测通过和已登记配置，都不等于宿主已触发。** 非 managed hooks 需要在宿主 Review hooks／Settings > Hooks（CLI 为 `/hooks`）审查具体定义，定义变化后可能需重审。不能直接改信任记录绕过审查。只有真实宿主事件触发并生成可回查收据后，才报告该会话已生效；当前活动聊天是否热加载还需实测。未生效时仍按每个人工节点与实质单元主动保存。

钩子只能保存实际文件、已提交内容和任务状态。未落盘的原话、尚在模型内部的草稿、没有声明或登记的外部文件，不能靠压缩钩子补救。原稿和新发现一形成就写入候选文件；每次人审停前执行[节点停前保存](node-persistence.md)。

### 显式绑定与读取

持久化项目初始化／接续后，若宿主给出了可核实的当前会话 ID 与 transcript 绝对路径，由助手绑定当前项目、真实授权范围和正在编辑的工作文件；换项目或文件位置后更新绑定。不能推测 ID、遍历其他聊天找相似名称或沿用另一会话映射。拿不到身份／路径时记“未绑定”，继续主动保存。

```text
python -X utf8 -B scripts/context_guard.py --config CONFIG --bindings ABS_REGISTRY bind
    --session-id ACTUAL_ID --transcript ACTUAL_TRANSCRIPT --project ACTUAL_PROJECT_DIRECTORY
    --scope ACTUAL_AUTHORIZED_SCOPE --material original=ABS_ORIGINAL --material research=ABS_RESEARCH
python -X utf8 -B scripts/context_guard.py --config CONFIG --bindings ABS_REGISTRY snapshot --session-id ACTUAL_ID
```

`ABS_REGISTRY` 是配置工作根内的绝对文件路径。`--material` 可重复，分类为 `original|research|creative|pending|next`；传真实现有文件，二进制原件也保留原字节。未分类的 `--file ABS_FILE` 保存为待归类工作件，不冒称主创原稿。已提交的五类材料可从前次检查点复用。

把 `hooks.example.json` 中两处脚本和 registry 路径替换为本机绝对路径，放入实际项目的 `.codex/hooks.json`，并按宿主审查信任。脚本不自行注册、不更改信任记录。`PostModelRequest` 仅在 `status=completed` 且 rollout 已有完整新鲜快照、达到提示信号时保存；相同事件去重，连续高位且 HEAD／声明文件未变不再加修订。若 hook 先于快照落盘，该次保守标未知，不猜测。`PreCompact` 不依赖高位判定，身份匹配后仍尝试保存。

回执保留已提交版本、恢复状态和实际捕获字节的 SHA256。节流索引／回执写入或锁清理失败不能抹去真实提交；已提交而恢复入口不全时按原操作重建。真实宿主触发的收据与手工接口测试分开记录。模型请求钩子只用于诊断，stdout 不作为一定进入聊天的提醒；核验本地回执及宿主钩子记录后再报告触发结果。

节流同时比较本轮绑定的范围、任务与文件分类，不能把“字节没变”当作任务没变。回执丢失时先查已验证的权威历史，精确重播只重建接续入口；版本冲突时保留原候选，重新核对当前 HEAD、分类和实际声明文件后，以新操作构造中途保存，不盲改旧 base。自动重建有次数上限，仍冲突时保留失败入口与原因，不能声称已保存。压缩存档还须保留原人工回交的展示稿与资料引用；原依据已变化时先回交新版，旧待决问题继续可查。

## 可控预算与判断

初始目标以指定比较编码（本项目采用o200k_base代理）测量，不称宿主真实token或安全阈值：

| 对象 | 初始可控输入目标 | 超出后的判断 |
|---|---|---|
| 技能入口 | 1200—2500 tokens | 超过3500审查路由/重复，不以删必要协议达标 |
| 项目短中枢 | 800—1500 | 保留导航/关键条件，完整对象外置并可达 |
| 当前任务新增包 | 通常4000—8000 | 超过12000拆分审查，必要原文仍完整覆盖 |
| 普通工具返回 | 通常500—2000 | 主动限量/分页，原文按需要定向分批 |
| 正文输出 | 按真实长度和当前深度预留 | 分段保存/组装，不降为摘要抵交 |

同时预算入口、系统/历史、任务包、未来工具返回、正文和其他预留，不只看输入文件。可靠遥测具备时使用B=max(0,C−U−F−O−R)：C有效容量、U已占、F后续工具、O输出、R其他预留，已算入U不重复扣。估算项与真实快照分开；没有可信C/U就不算精确剩余，更不默认200k窗口。

入口变短、拆文件、摘要和缓存不会释放已进入本轮历史的上下文。比较预算控制新增材料，不证明质量或实际窗口安全。文件数、字符数和token代理之间不可混报。

## 三种工作状态

继续：必要依据和输出空间足以完成一个有意义单元，保持当前工作；减量：大包、截断、重复/无关材料、版本混淆、无法定位有效决定等信号出现，先保存再缩查询和返回；接续：当前必要条件/空间不足以可靠完成，保存并核检查点，按宿主实际能力恢复。

减量/接续不是终止已授权工作或降低内容要求。没有遥测仍可据工作信号操作，不能把信号换算为百分比。未经请求不新建用户聊天，不能宣称主动清空上下文或擅改其模型/设置；新对话/子Agent的授权和机制依当前宿主规则。

## 目录、任务包与按需原文

主控维护完整目录、稳定ID/版本和未读/例外；短视图放本轮协作轮次、当前人工节点及待答复事项、当前问题、本轮有效决定、关键条件、未决、已存在正文和下一任务入口，完整来源/历史外置。目录分页要给总量、当前页、列出范围、未覆盖范围和下一页，不能首批当全量。

当前任务先识别完整目录，再定位必读核心原件、相关正文、直接及实质间接依赖，按[交接与任务包](handoff-and-task-packs.md)回读。搜索可从1—3个候选及必要上下文起步，数量是减量策略，不限制必要证据；需要整章/全文时分批覆盖。不能只凭首命中或摘要判断例外不存在。

相同未变材料复用路径、版本和来源绑定摘要，需要具体判据再回原文。专业reference只读当前命中节，用户要求完整通读时仍完成全部范围。不能把全部旧入口、全案例库、所有工具说明/会话拼接成包。

## 大结果可靠转存

预计结果大时在取得完整结果的通路中保存原文/结构到项目文件，检查存在、内容可读、大小/指纹或页/记录完整性后，再返回短预览、总量、实际取得范围、路径/定位、截断/访问限制和下一读取位置。不要在模型先收完整结果后才声称已减少本轮占用。

工具只能取得/显示部分时保存真实已得内容并明确不完整，记录未得范围及补取；不能把被工具截断的返回保存成“全文”。仅设置max_output_tokens不是主动限量，更不是完整转存证明。HTML长行、base64、压缩JSON、大表先提取所需字段/段落或分页；索引仍保留原文件入口。未可靠保存的结果不能先宣称已转存，保存失败保留实际状态与重试/恢复路径。

并行检索的合计返回也有预算，每人各返完整资料再汇总会重载主控。主控收到短结论、位置、版本、实际读看范围、未决和候选，必要时回关键原文；子Agent自报完成不代接收审查。

## 来源绑定摘要

摘要注明来源ID/路径、版本/指纹、生成时间、原文范围、支持内容、关键例外/限制、未读/未决、当前采用及重核触发。它是导航，规则、预算公式、完整叙事、作品和专业条件回原文核；不能不断二次压缩直到只剩口号。

源件变或新事实推翻判断时使相关摘要/审查待复核，更新实际正文后再摘要；指纹相同不能证明动态报价/档期/权限仍有效。摘要不能将用户纠正、范围排除、授权和来源冲突漏掉；旧决定恢复时仍核当前条件。

## 检查点与断点

人工节点回交前执行 `pause`，把原稿、研究、创意取舍、待确认及下一步五类索引同实际回交稿保存为不可变修订，自动生成并回读恢复入口。新人工确认必须引用同轮同节点、所示材料仍匹配的保存凭证。完整步骤与节点落点见[节点停前保存](node-persistence.md)。工作单元和压缩前的 `context_save` 不代表人工放行。

记录补充 `required_refs` 与 `fingerprint_version`，恢复时重新生成同算法的目录和指纹文件，不能混用旧HEAD原件与新HEAD任务包。记录项目ID/绝对路径、权威/基础版本、当前协作轮次、人工节点、待人回答的问题、本轮已放行范围、当前任务/用途、完成单元/位置、真实正文或候选、依据/决定、已读范围/未读、阻断/未决、旧项/废止限制、下一具体动作/必读入口及核验。正文先写并回读，再更新指针/状态；拟保存路径不当已存在文件。

实质单元形成后、模块切换、大批研究前、已知交接/压缩/结束前保存。长稿可以按稳定章节分段保存，记录已完成/尚缺范围，未完整组装不称完整终稿。重要保存采用实际运行库事务/候选机制，不能编辑权威快照冒充提交；具体命令、冲突、锁、修复/回滚边界见[运行协议](runtime-protocol.md)。

恢复核项目匹配、HEAD/权威版本、协作轮次、本轮研究回交及接笔范围、真实路径/内容、来源和输入指纹、最新用户纠正/决定、剩余/失效条件，必要时回原件。缺失、冲突、过期或历史回滚时降低相关状态并定向核，不按旧摘要直接执行。真实外部事件不能被本地回滚撤销。

跨对话续写某章时，从当前交接中取本章的问题、承接关系和[主创原稿定位](author-and-chapter-writing.md)。先打开所指原段及其批注、上章实际结尾与本章已有正文，确认哪句话要保留、哪条路已放弃、哪些新条件已经生效。在当前放行的章节范围内给读者写下一段，保存实际成稿落点及尚未解决的衔接。待人审阅的章或章组先回交，按真实答复继续。旧任务包遇到新决定时重取相应输入，再检查此前已完成的相关章与附件。

从头重做或重定目的时，先保留当前原件和外部事件，按[旧案重开](workflow-and-decisions.md#旧案从头来过)与运行协议建立本轮协作记录。核哪段原稿和旧选择继续有效，重新取得当前委托及接笔范围。仅在任务文字里写“回到研究”或恢复旧生产状态，不能作为本轮开写依据。

## 长全案与协作

完整生产每个约定模块和单元，按阅读用途分段统一编辑，再跨模块回读名称/内容/规则、时间地点/入口、人物/权利状态、人数口径、资源/费用、权益、素材/稿件、服务与测量。需全文审查的实际覆盖留记录，不能用标题目录代表通读；无关重复减少，内容深度保留。

组装引用同一有效正文与版本，不把内部研究全文塞客户件，也不复制第二主账。组装后核来源/模块存在、依赖/未决、实际正文完整与可读、附件/编辑性和输入版本；脚本只能机械拼接不能代语义/资源/受众验收。

首版默认串行，同一AI可持不同专业视角。有授权且适合才团队：独立补查、冻结输入上的内容单元或核验可并行，方针、共同事实、成本、冲突与最终合并由单主控维护。限定任务文件和短结果仍须实际回读；全历史继承不称冷读，跨机器同步未实测不称具备。记录重复输入、耗时/合并负担和收益，不足则串行，不为团队名额扩大任务。
