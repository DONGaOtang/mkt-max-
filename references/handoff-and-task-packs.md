# 第一阶段交接、任务包与接手

适用：研究转生产、模块切换、既有项目导入、新对话接续或多人协作。只交任务必要可访问材料，但主控须保留完整资料与历史入口。正常接续沿当前轮次继续；主创要求从头重做时先核本轮继承范围并重开协作轮次。

## 第一阶段交接

正式生产先核本轮 A 委托、研究发现回交、B 方向及接笔委托的真实回复，包含由谁看过什么、选了什么和允许写到哪里。已经写好的推荐与原型可以直接交人讨论。缺失人的决定时，保留候选、待决问题和下次入口；接续时从上次停下的位置继续。纸面研究已就绪，只代表已有材料可供判断。正式项目的登记与兼容规则见[运行协议](runtime-protocol.md)。

首份正式交接由助手依[主创底稿与逐章写作](author-and-chapter-writing.md)整理。写作者应能只打开交接及其原件，就找出主创亲笔原段、编辑范围、选中与弃用理由、研究或推演改变的写法，以及各章从哪项成果接手。

| 信息 | 需要交出的实质内容 |
|---|---|
| 身份与版本 | 项目ID、绝对路径、当前权威版本及协作轮次，作者/委托与读者用途 |
| 需求与范围 | 有效契约、四种适用状态、深度/格式、用户最新纠正及排除项 |
| 方针与决定 | 本轮研究发现怎样被采用、主创选了什么、本次授权写什么及用途和深度，分别给出原话与位置。投入、对外说法、资源等有独立决定时，注明权限、所依事实和触发重审的条件 |
| 内容原料 | 采用原作/事实/作品/服务、主创原文版本及精确定位、允许的写法和公开范围 |
| 完整资料入口 | 全目录及分页、原件/URL/定位、版本、同源/限制及未读范围 |
| 判断充分性 | 可写案/条件写案/阻断相关定稿、反证、仍不能证明的部分 |
| 未决 | 具体问题、影响、是否阻断、责任职能、补查/决定动作、定稿边界 |
| 已有内容 | 研究中生成的场景/原型、规则、文案、费用与执行预检的真实路径和状态 |
| 第二阶段任务 | 每章读者问题、原稿/原型/依据与开篇位置、承前及交给下章的内容、成稿核对位置；工作件另注明接收者和完成标准 |

原型和早期正文保留原貌，在本轮接笔范围内继续深化。局部任务可引用有效交接，补本轮变化；重新选择按[工作流与决定](workflow-and-decisions.md)处理，并更新受影响的交接。

## 补充依据与版本

运行库只按对象依赖选择必读，`task` 是任务说明，没有语义检索功能。发现目录内本轮相关而尚未登记的依据，使用 `resume(..., required_refs=["source:S3"])` 或重复 `--required-ref source:S3` 扩充必读。与既有依赖同样核项目、权限及分页；不允许借补充依据获得受限原件。补充引用和 `fingerprint_version=2` 留在接续包中，恢复后仍核当前HEAD。临时阅读不改永久依赖，实际采用的来源/决定/对象随模块提交进入正式引用。

新来源指纹绑定原件和元数据；产物指纹仍表示字节。旧复核可保留历史结论，但未绑定来源元数据时，不作当前限制已核的证明。算法兼容与载荷见运行协议，不能只换版本号重用旧输入。

## 模块任务包

任务包是导航和限定输入，完整内容在文件中。按需要包含下列字段，不要求独立十二张表：

1. 项目ID、绝对路径、权威版本及当前基础版本。
2. 模块/对象、实际问题、当前范围、正文深度及适用状态。
3. 作者、读者、接手动作、用途、本轮已授权工作、章节顺序或明确批量范围、当前待人答复事项。
4. 有效方针、决定、阶段交接与其来源入口。
5. 完整资料目录、分页覆盖、本轮必读原件及精确位置。
6. 相关正文及实际版本、内容单元/场次/资产，直接依赖及实质间接依赖。
7. 共同事实和主维护位置、用户最新纠正、旧项失效及例外。
8. 条件草拟边界、定稿阻断、未决责任与补查。
9. 真实输出正文/稿件/工作件、附件、所需格式及完成标准。
10. 交出者、接收者、截止、验收与退回/异常。
11. 候选位置、提交入口、操作ID及冲突/重读要求。
12. 比较编码、输入/工具/正文输出预算和分段安排。

能影响本轮选择、规则、技术、费用或承诺的间接条件不能因无同名关键词漏掉。指向来源的简短包不能使参与者自行获得未授权合同/名单；主控保留权限与必要信息过滤。宿主文件权限隔离未实现时不能把限定任务包称系统隔离。

## 全量识别与真实阅读

先识别资料目录及当前索引覆盖，避免遗漏来源存在；再选择当前核心原料、决定、必要限制、相关正文和依赖的原始内容。记录“已列出/未列出”和“未读/部分/全文”两种覆盖，不能互代。

核心判断、规则、预算公式、作品内容、例外和必要专业条款须实际读到对应原文；只核局部接口可定向读条款及父章节上下文。需要判断整章结构、故事、全案或用户要求通读时，分批完整走读并记录覆盖；“搜索无命中”不能证明全篇没有例外，首命中也不能证明没有后文。

旧摘要要核源版本、范围、限制及当前适用性，冲突时回原件；不能摘要再摘要以获得虚假的完整继承。参考图/视频另记已看页/帧/时段，文本抽取不当视觉阅读。source、read_scope及分页字段的实际格式见[运行协议](runtime-protocol.md)，脚本不验证语义读取真实性。

## 开始、提交与接收

开始前核项目、当前版本与协作轮次，读短中枢、本轮有效决定、研究回交与接笔范围、任务必读原文及相关正文，检查用户纠正、旧项、例外和缺口；保存实际读看范围。材料变化时核本轮使用版本，必要时生成新任务包，不继续沿旧包定稿。

完成后先写真实候选，核其可读与内容，再提交基础版本、采用来源、决定和共同事实变化、直接/间接影响、未决、实际读取及本次核验。提交规范和命令沿运行协议，不手工改HEAD、快照或交易记录。保存失败不能称已交或已记住，脚本成功不能称已被客户验收。

主控接收后实际回读关键正文，检查约定内容、事实、数量、接口及输入版本；修订合并后更新索引、状态和受影响下游待复核。章稿按逐章或已获托的章节组回交人审，记录留、改、退回和后续写作范围。候选内容、可评审正文、资源已确认与用户批准分别表达。“完成”绑定具体文件/版本、用途及验收对象。

基础版本冲突时保留候选，读取最新版本与变化，比较内容后重基线修订，用新操作ID提交；只替换base值不能代核对。新对话带项目路径和当前任务入口，不带全历史；无写权限只交候选，由主控合并。继承历史的子Agent仍可能共享偏见和旧约束，不能称独立验证。

## 退出与下一接手

检查点保留本轮人工节点、待人回答的问题、允许继续的范围、完成位置、实际候选/正文、版本、依据和读取覆盖、尚未读、未决及阻断、旧项限制、下一具体动作与必读入口。模块变更、大批研究前和已知交接前保存；每个实质单元形成后保存，不只等最后全案。

接收动作至少可回答：拿哪份真实内容、凭哪条规则或规格、何时开始和结束、谁确认、遇到异常交谁。仅有任务表、目录、摘要和“由执行负责”不能替代接手材料。相关具体格式见[人员与设计交接](staffing-and-design-handoff.md)、[执行与复杂度](execution-and-complexity.md)。
