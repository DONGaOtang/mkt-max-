# 主创底稿怎样交给下一章

第一阶段由主创提出、选择和修改想法，助手查材料、试写、找反证，将发现回交主创补稿和决定使用重点。第二阶段在明确接笔委托后由助手逐章写，并按约定节点回交实际章稿。完整方案执行下列交接；只委托改一段时，取对应原段、修改意见与相关条件，完成实际改稿。

## 第一阶段留下原文、原型与取舍

1. **保留原件。** 收到主创稿或批注就留原版本，记作者、日期或版本、标题和段首短句。纸稿用页/行，音视频用时间段；助手试写与主创亲笔稿分别署明。后续摘录都能回到原位置。
2. **从实际批注识别可怎样写。** 只标会影响成稿的段落。照顾主创选定的措辞、允许的改动和对外使用范围。未知处先保存原文，在授权内给可逆试写；若编辑权或公开范围会改变交付，向主创提出该处的具体选择。

| 主创对这段的意见 | 助手怎样继承 | 写完怎样核 |
|---|---|---|
| 逐字保留 | 在指定章、位置或用途放回精确原句，保留字词、语序和标点 | 对照两个版本中的原段，核落点与篇内重复。授权只限一处时只出现一处 |
| 可以润色 | 沿用原意、关键事实和语气，按该章读者改句子 | 看改前改后，指出怎样保住意图，以及有无扩大强度或承诺 |
| 只保留意图 | 从原段提炼“谁在什么情境下做什么、得到什么”，自行选择具体表达 | 读者能从成稿指出这个动作与所得。正文使用新写者的表述 |
| 弃用、暂缓或不外发 | 记下决定者、原话、理由、适用范围；暂缓项另记何种变化值得再议 | 在相关章、附件及组装稿检查同义改写、机制和操作后果，内部历史留原处 |

3. **把选中的创意写成可续写的一幕。** 底稿里保留实际场景、选择或放弃它的理由、比较过的替代、研究中改变写法的那个细节。动态事实注明何时要重核。消费者反应、桌面推演、真人观察、实际资源确认各自标清。将尚待核实的事项写成“谁核什么、影响哪个承诺、何时需要答案”。
4. **把内容送到合适的章。** 助手在现有方针交接正文写出全案要说明的一句话，再为每个实际受托章节写一行。依次说明该章回答读者什么问题、调用哪个原段/原型/依据、从前章接什么、给后章什么、交稿时在哪一段核。并列章节写各自用途。原文可只出现一次，其他章分别承担流程、资源、文案或判据的含义。

交接时分别记下本轮研究发现怎样被主创使用、主创选定了什么、这次委托助手写哪几章及用途和深度、哪些业务承诺由谁决定。原稿与允许的内部试写可以先保留；缺少开写委托，停在共同研究。另有投入或外发条件时，写明会卡住哪个承诺，并保留可先写的内容。接手者回原件复述主创保留、放弃或尚待判断之处，给主创看章节安排和接笔范围。已有本轮明确接笔答复时按原范围开始，单纯选中创意时继续第一阶段。

例如，假定主创要求导览章开头原样用“先听一遍，再决定从哪里看。”，选定让观众自主选择顺序，又放弃集章换礼。导览章留下这句开场并写第一段声音；路线章写观众听完从哪两个入口选择；岗位卡写中途到场者如何加入；评估章观察人能否自行选路。每章要补不同的内容，检查岗位卡和预算时也要找盖章、奖品及其变体。以上为写法示例。

## 第二阶段实际怎样写一章

1. **取当期材料。** 核项目、当前版本及本章范围，打开交接所指的主创原段、有效决定、所选原型、该章采用的研究和共同事实。读上一章实际结尾及有关联的已写段落。材料太长则分段打开，保留原文位置。
2. **先解决这一章的读者问题。** 把上章已经交代的事实用作起点，展开该章独有的现场、依据、取舍或工作细节。报价、资源、效果等有条件处写出条件。写完检查下一章需要的对象或事实是否已经建立，必要时改动相邻段落使衔接自然。
3. **留下可回查的落点。** 在本章内部核验记录里写“原件版本及段落 → 成稿版本、章标题及可唯一找到的句子 → 此次如何继承”。逐字项一字一字对，润色项核意思，意图项核实际动作。弃用项同时读现场机制、传播和附件；换了名称仍在做同一件事，也须删改。
4. **保存并交本章审阅。** 回读真正写出的正文，记录解决的问题、尚缺条件和下一章接笔处。向主创展示这一章，等其留、改、退回及下一步答复。当前明确委托已覆盖一组章节时可连续写完该组再回交，范围外的下一章等新委托。版本以成功提交的回执为准。内部草稿可直接供章节反馈，采纳范围绑定所看的实际文字和版本。最后按约定读者用途走读整稿；能安排独立读者时，让对方仅凭实际稿件完成接手任务。记录谁实际读过、卡在哪里。核每个必保片段的落点及取舍后果，再交 C 整稿审阅。

## 一条条件改变后怎样回到整份方案

先核新消息的出处、有效时间与旧值。问它推翻了哪一项判断。目的或参与动机变了，重查需求并将方向交回主创；投入依据失效，重算替代用途、改写预算建议，交预算负责人重审；资源容量或产品事实改变，重核接收或公开承诺。原句若含失效承诺，把原件和新依据交主创处置。某项业务条件改变时，让仍然成立的表达和原稿继续有效。

从旧条件反向找使用它的地方。除已登记依赖外，再按读者承诺、岗位动作、数量推导和语义通读相关章及附件。例如场地缩时，检查是否少一轮、报名是否仍允许旧名额、岗位覆盖和费用是否有变化、评估分母是否要重算。对受影响处保存改前/改后定位和理由，对不受影响处保留原稿。再用原先的消费者处境和现场扰动复跑关键环节，回读组装稿，记录修正结果、仍需何种实测及所审版本。

## 正式项目用现有接口落盘

- 本轮原稿、带批注的修订稿、研究发现及其回交答复、接笔委托与章节反馈登记为 `source`，用 `locator`、`version` 和 `read_scope` 定位。真实决定沿用 `change` 的 `decision`，事实或资源变化记对应实体及其来源。方针交接的 `file` 保存上述文字和章节安排，`source_ids` 指实际采用的来源，`inventory_source_ids` 覆盖完整目录，`unresolved` 写明影响对象和解除条件。主创逐字要求与弃案理由放在有来源的交接正文和决定原件中。
- 旧案重启先按运行协议建立当前协作轮次，核主创对旧原段和取舍的继承意见。每章使用契约的 `module_id`。用 `resume --module` 取任务包，实际需要的漏项以 `--required-ref` 补读。提交本章 `file` 时，在 `source_ids`、`decision_ids`、`fact_ids` 或 `depends_on` 登记实际采用的引用，在 `acceptance_evidence` 写出已核的原段、成稿落点与结果。章间只有真实的内容依赖才登记，单纯章序由契约维护。
- 新条件经 `change` 写入时，`impact` 指明受影响对象。逐章改写并回读正文、岗位件及金额等实际产物，再组装所需的阅读稿。运行库按显式依赖标记待复核；主控承担含义、遗漏和跨章连贯的核对。字段、接续与组装的完整约定见[运行协议](runtime-protocol.md)。
