# 人工节点停前保存与恢复

适用：委托、研究回交、方向取舍、接笔、章审、整稿审阅和条件变更重审。正文与研究先落盘，节点收尾由 `pause` 一次提交；材料保存成功并核实接续入口后，才回交并等待人。命令与字段以[运行协议](runtime-protocol.md)为准。

## 停下前实际做什么

1. 把本次展示给人的实际简报、研究稿、原型、章稿或变更比较写入文件，回读内容。聊天里的新原话也保存为原话，注明说话人、位置与时间；助手整理稿另存，不替换主创原文。
2. 收齐下面五类材料，保留原件、来源和版本。每类明确本次新增、引用已有内容或确无新增；无材料就写原因，不用占位摘要装作已保存。
3. 写清当前停在哪里、正在等谁回答什么、已有授权范围、答复后第一项具体动作。新问题、尚未选定的方向和助手建议分别表达。
4. 调用 `pause`，带当前基础版本、唯一操作 ID、真实回交文件、五类清单、材料引用和下一步。脚本在事务中保存原件字节、分类索引和指纹，发布新版本，再生成并核验恢复任务包。
5. 检查返回的提交与恢复状态。保存失败时保留原件及候选，处理错误，不能对人说已安全保存。若事务已经提交、仅派生任务包失败，从返回的新版本重建恢复入口，不能把已成功事务重放成另一笔写入。
6. 给人展示实际内容和具体待决问题，在授权边界停下。取得真实答复后，登记原话来源，并用 `checkpoint_id` 指向同轮同节点、材料仍匹配的已保存回交。保存凭证不等于人的确认。

| 分类 | 保存的实物与目的 |
|---|---|
| `original` 原稿 | 主创亲笔、批注、新念头及逐字保留／可润色／仅保留意图等编辑权限。供第二阶段回到原句接笔。 |
| `research` 研究 | 已取得原件、出处、实际阅读范围、发现与反例、动态信息取得时间及重查条件。供恢复后分清证据与假设。 |
| `creative` 创意取舍 | 并存方案、试写／原型、采用／弃用／暂缓及理由、未采纳的反对意见。防止续写把旧候选当定案或重新提出已弃路线。 |
| `pending` 待确认 | 人需要作的判断、谁有权回答、影响什么、仍可继续什么。供恢复后准确停在原边界。 |
| `next` 下一步 | 答复后第一项动作、必读原段和已有稿件位置、允许范围与禁止越过的条件。供接手者直接继续。 |

分类是材料索引，不要求主创填五张表。同一原件可服务多个目的，引用现有正文和来源；助手负责整理。原件只读，快照保留已保存版本，工作文件后来变化须再次保存。候选不因进入检查点自动成为正式章节或选定方向。

## 各节点额外核什么

| 当前节点 | 保存时的关键落点 | 恢复后先做什么 |
|---|---|---|
| `brief` 委托 | 本轮目的、继承／重议范围及已给资料 | 回读主创原话，等或采用实际委托答复 |
| `research` 研究回交 | 原件及本次展示的发现、反例、使用建议 | 回到原文和主创正在写的位置，按其研究取舍继续 |
| `direction` 创意与取舍 | 实际原型、差异、成本与弃用理由 | 维持并存／暂缓状态，取得实际选择；不据此自行进入第二阶段 |
| `writing` 接笔 | 有效交接、原段编辑权、章节顺序或明确批量、读者用途 | 只写获托章；所依交接和模块须在回交保存范围内 |
| `chapter_review` 章审 | 实际章节、所示修订和正文指纹、待改及承接处 | 按原稿反馈修改；逐章模式未放行就不写下一章 |
| `delivery` 整稿 | 实际阅读稿与同版 manifest、采纳范围和未决 | 保持所审版本，按真实答复登记整章或片段采纳 |
| `change` 条件变化重审 | 新旧条件、受影响原段、独立仍成立的选定片段、可选改法 | 只重审受影响取舍，保留未受影响的主创原句 |

这些节点可以多次回交；人数和审批次数由本次要作的决定决定。已明确授权不再重复索取。轻量改一句可以直接完成；如果要停下来等人或跨对话接续，同样先保存本次实际成果和五类索引。尚未建持久化项目时，只为这次保存初始化轻量项目即可，不补造整套方案契约。

## 中断后如何接回

先 `resume` 读取当前 HEAD，核项目、协作轮次、最新节点保存记录和完整分类索引。打开保存的原件和回交正文，核字节／指纹与路径，读待确认和下一步，再核当前有效授权及条件变更。任务包只是导航，不能代替原稿、研究原件或章稿。

中断发生在发布前，以原 HEAD 为准；候选与暂存保留待比较。发生在发布后，检查操作 ID 和新 HEAD，已提交的记录直接恢复；派生包可以重建。残留锁只在确认原进程已结束、核完 HEAD 和暂存后处理，不能看到锁就强制清除。恢复不自动补批、不让过期方向或旧开写权限复活。

`context_save` 用于工作单元、中途打断和压缩前的保存，使用相同分类方式，但不开放任何人工权限，也不伪造一次人工节点。此动作保存真实文件和已记录状态，不能从模型内部提取未落盘草稿。宿主钩子与遥测见[上下文与恢复](context-and-recovery.md)。
